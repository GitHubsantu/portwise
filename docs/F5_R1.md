# R1 gateway ownership — user-run isolated recheck

Copy-only steps, one at a time. Not executed by the agent. Use the isolated VS Code profile and test home, never the real Codex home. Disable the Codex panel when testing fake auth.json. No login/account/configure action is needed for these gateway-only checks. Use the new hash-verified VSIX; previous second-PC acceptance does not cover this changed ownership protocol.

1. **Record the test-home baseline.** In PowerShell, confirm this is the intended test folder. Show config/history/.env hashes and auth.json metadata only; do not display credentials.

   ```powershell
   $pwTestHome = 'E:\portwise-test-codex3'
   $pwNames = @('config.toml', 'history.jsonl', '.env')
   $pwBefore = foreach ($pwName in $pwNames) {
     $pwFile = Join-Path $pwTestHome $pwName
     if (Test-Path -LiteralPath $pwFile) {
       [pscustomobject]@{Name=$pwName; Hash=(Get-FileHash -LiteralPath $pwFile -Algorithm SHA256).Hash; Length=(Get-Item -LiteralPath $pwFile).Length; LastWriteTime=(Get-Item -LiteralPath $pwFile).LastWriteTime}
     }
   }
   $pwBefore
   Get-Item -LiteralPath (Join-Path $pwTestHome 'auth.json') -ErrorAction SilentlyContinue | Select-Object Length, LastWriteTime
   ```

2. **Start / Stop / Restart.** In the isolated profile, set portwise.codexHome to that exact test path. Use port 47831 only if free or known to belong to this profile. Start Gateway, Stop Gateway, Start Gateway, Restart Gateway. Check badge/log and Diagnostics. A current-build owned daemon should verify and respond. No Codex-home file should change. If an old daemon blocks startup, continue to step 4; do not kill an unidentified PID.

3. **Owned daemon after reload.** Leave the current-build gateway running; Developer: Reload Window, then Start Gateway. Its saved state/secret plus fresh proof should permit reuse. Diagnostics health/daemon/local-token should PASS. Stop Gateway should free the port. This is different from an orphan without this profile's state/secret.

4. **Unverified/orphan on 47831.** Start a controlled current-build daemon in the first isolated profile. Use a second fresh isolated profile with the extension installed, autoStartGateway disabled, the same port and its own temporary Codex home. The second profile has no matching saved daemon state/secret. Start must report the occupied port; Stop/Restart must refuse ownership, leaving the first daemon running. Diagnostics must not claim verified ownership or accepted local auth. Verify the first profile still sees its daemon. Stop it only from that owning profile. For a legacy daemon without proof support, use the old owning profile/version to stop it after identifying it, or choose another port explicitly; the new build must never adopt/stop it or send credentials. Pure instanceId echo/replay/socket-handoff cases remain automated tests, not manual credential experiments.

5. **Diagnostics and unchanged files.** With the owned daemon running, run Diagnostics and copy the redacted report; then stop it and rerun. Running should prove ownership; stopped should provide Start Gateway guidance without starting/writing anything. An unverified listener must receive public probes only and remain untouched. Compare the test home to step 1; auth.json Length/LastWriteTime must also match. Do not inspect real-home files.

   ```powershell
   $pwAfter = foreach ($pwName in $pwNames) {
     $pwFile = Join-Path $pwTestHome $pwName
     if (Test-Path -LiteralPath $pwFile) {
       [pscustomobject]@{Name=$pwName; Hash=(Get-FileHash -LiteralPath $pwFile -Algorithm SHA256).Hash; Length=(Get-Item -LiteralPath $pwFile).Length; LastWriteTime=(Get-Item -LiteralPath $pwFile).LastWriteTime}
     }
   }
   Compare-Object $pwBefore $pwAfter -Property Name, Hash, Length, LastWriteTime
   Get-Item -LiteralPath (Join-Path $pwTestHome 'auth.json') -ErrorAction SilentlyContinue | Select-Object Length, LastWriteTime
   ```

Expected comparison: no rows. Report PASS/FAIL and metadata only. Stop test daemons from their verified owning profiles; keep isolated login/storage private. No publish/tag, blind process kill, real-home access or automatic cleanup is part of this checklist.
